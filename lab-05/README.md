# API Response Requirements

## Зауваження

1. Контролер повертає сутність Item напряму, а не DTO.
2. CRUD методи повертають Item або void, а не ApiResponse.
3. HTTP коди відповіді не виставляються, на всі запити приходить 200.
4. Якщо item не знайдено, GET повертає порожню відповідь замість 404.
5. getAll повертає всі записи без пагінації.
6. При створенні і оновленні дані не перевіряються.
7. PUT і DELETE не перевіряють, чи існує item.
8. У getItemByIdAsApiResponse при 404 у data потрапляє список з null.
9. Пагінація не перевіряє від'ємні page і size.
10. Немає єдиної обробки помилок.

## Що зроблено

1. Додані ItemRequest і ItemResponse, мапер ItemMapper перетворює Item в DTO і назад.
2. Усі методи контролера повертають ResponseEntity з ApiResponse, один item віддається як список з одного елемента.
3. GET /api/v1/items/{id} повертає 200 або 404.
4. GET /api/v1/items повертає сторінку з PaginationMetaData, за замовчуванням 5 елементів.
5. Для page менше 0 і size поза межами від 1 до 100 повертається 400.
6. POST повертає 201, при неправильних даних 400.
7. PUT /api/v1/items/{id} повертає 200, 400 або 404.
8. DELETE /api/v1/items/{id} повертає 200 з видаленим item або 404.
9. Додано GlobalExceptionHandler, усі помилки повертаються як ApiResponse з кодом і зрозумілим errorMessage.
10. Неправильний JSON і неправильні параметри запиту повертають 400.
11. Дублікати /response/{id} і /page видалені, їх функціонал тепер в основних методах.
