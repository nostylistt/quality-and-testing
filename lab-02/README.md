# Good Bad Code

## Зауваження

1. Унікальні слова шукаються через contains по рядку, тому слово губиться, якщо воно частина іншого слова. Через це з результату зникли the, to, he, of.
2. Рядок унікальних слів збирається через += у циклі, це дуже повільно.
3. Частоти рахуються вкладеним циклом, кожне унікальне слово порівнюється з усіма словами тексту.
4. Сортування за кількістю зроблене через вирізання цифр регуляркою з рядка "слово кількість".
5. Весь код в одному методі main, немає окремих методів.
6. void main() без класу не компілюється на JDK 21.
7. Шлях до файлу і число 30 захардкоджені, якщо слів менше 30, програма падає.
8. Файл читається через new String(bytes) без вказаного кодування.
9. Змінна size не використовується, Arrays.sort(words) зайвий.
10. Апостроф розриває слова, didn't стає didn і t.
11. Якщо текст починається не з літери, split повертає порожнє перше слово.
12. Час заміряється через LocalDateTime замість System.nanoTime().
13. Шаблонний заголовок IntelliJ, коментарі типу // 400 000, неохайне форматування.
14. У репозиторій додані файли IDE (.idea, SorcerStone.iml).

## Що зроблено

1. Main переписаний як звичайний клас, код розбитий на методи splitIntoWords, countFrequencies, findTop.
2. Частоти рахуються через HashMap, результат правильний і програма працює швидше.
3. Топ слів сортується за кількістю через Map.Entry, без роботи з рядками.
4. Шлях до файлу, кодування і розмір топу винесені в константи.
5. Файл читається через Files.readString з кодуванням windows-1252.
6. Слова з апострофом рахуються як одне слово, порожні слова відкидаються.
7. Час заміряється через System.nanoTime().
8. Видалені шаблонні коментарі, код відформатований.
9. Файли IDE додані в .gitignore.
