# Memory Optimization

## Зауваження

1. Весь файл читається в один рядок через Files.readString.
2. toLowerCase і три виклики replaceAll щоразу створюють нову повну копію тексту.
3. split і toList створюють масив і список з усіх слів тексту, хоча потрібні тільки лічильники.
4. Лічильники зберігаються як Integer, кожен merge створює новий об'єкт.
5. Для топ-30 сортуються всі унікальні слова.

## Що зроблено

1. Файл читається посимвольно через BufferedReader.
2. Слова розбираються без регулярних виразів, використовується один StringBuilder.
3. Кожне слово одразу додається в лічильник, без проміжного списку.
4. Лічильники зберігаються в HashMap<String, int[]> з початковим розміром, без Integer.
5. Топ-30 знаходиться через PriorityQueue на 30 елементів.
6. Програма виводить час виконання і пікове використання heap.
7. Результат топ-30 збігається з попередньою версією.

## Порівняння

Середнє за 10 запусків, JDK 21.

| | До | Після |
|---|---|---|
| Час виконання | 182 ms | 46 ms |
| Виділено пам'яті | 13 553 KB | 4 302 KB |
| Пікове використання heap | 14 336 KB | 6 758 KB |
| Мінімальний -Xmx | 8 MB | 3 MB |
