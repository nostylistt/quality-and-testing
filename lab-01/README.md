# Code Review

## Зауваження

1. Геттери і сеттери названі takeA() / putA() замість getA() / setA().
2. Назви методів perim() і equilateral() незрозумілі, краще getPerimeter() і isEquilateral().
3. Конструктор не перевіряє сторони, можна створити трикутник з нульовими або від'ємними сторонами.
4. Немає перевірки нерівності трикутника, можна створити трикутник 1, 2, 10.
5. Сеттери і порожній конструктор дозволяють отримати некоректний трикутник, клас краще зробити незмінним.
6. Числа double порівнюються через ==, потрібно порівнювати з похибкою.
7. area() чотири рази викликає perim() і використовує магічне число 0.5.
8. Конструкція if (...) return true; else return false; надлишкова.
9. Неохайне форматування: різні відступи, подвійні пробіли, немає пробілів навколо операторів, else без дужок.
10. Main це шаблон IntelliJ з коментарями //TIP, клас Triangle ніде не використовується.
11. void main() і IO.println працюють тільки на JDK 25, на попередніх версіях код не компілюється.
12. У репозиторій додані файли IDE (.idea, Triangle.iml) і немає тестів.

## Що зроблено

1. Клас Triangle став незмінним: поля final, сеттери і порожній конструктор видалені.
2. Методи перейменовані: getA(), getB(), getC(), getPerimeter(), getArea(), isEquilateral().
3. Додана перевірка сторін і нерівності трикутника, при помилці кидається IllegalArgumentException.
4. Порівняння double виконується з похибкою.
5. Півпериметр в getArea() обчислюється один раз.
6. Код відформатований.
7. Main переписаний як звичайний клас, показує роботу Triangle і перевіряє основні випадки.
8. Файли IDE додані в .gitignore.
